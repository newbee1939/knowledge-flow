# 手順

1. **対象**: 引数（`YYYY-MM-DD` / `YYYY-MM` / `all`）に一致する `docs/blog/posts/*.md`。引数がなければ**直近 7 日分**（`ls -1 docs/blog/posts/*.md | sort | tail -7`）。
2. **機械的に洗う**: 見落としやすい型は先に grep で当たりを付ける。

    ```sh
    # ひらがな＋長音符（「くろーらー」など、外来語がカタカナに変換されなかった跡）
    grep -nE '[ぁ-ん]ー' docs/blog/posts/*.md
    # 記号の重複・全角カッコの閉じ忘れ
    grep -nE '(。。|、、|」」|（（)' docs/blog/posts/*.md
    ```

3. **読む**: 対象ファイルを頭から読み、下記の観点だけを見る。文章の良し悪しは見ない。
4. **修正**: 該当箇所を Edit で 1 か所ずつ直す。**直した箇所と理由を最後に一覧で報告する。**
5. **確認**: `npm run build` が通ることを確かめる（frontmatter や Markdown 記法を壊していないか）。
6. **commit**: `git add docs/ && git commit -m "fix: 誤字脱字の修正"`。push はしない。

# 見る観点

- **変換ミス**: 外来語がひらがなのまま（「くろーらー」→「クローラー」）、同音異義語の取り違え（意外／以外、保証／保障、対象／対称）
- **脱字・衍字**: 助詞の抜け・重複（「〜をを」）、送り仮名の誤り
- **表記ゆれ**: 同じ記事内で同じ用語が違う表記になっていないか
- **固有名詞**: 技術・プロダクト名が公式表記どおりか（`npm` を `Npm` にしない、`xAI` を `XAI` にしない）
- **記号**: 閉じていないカッコ・引用符、句読点の重複
- **数値と単位**: 本文中の数字が見出しやリンク先と食い違っていないか（明らかな矛盾だけ）

# やらないこと

**このスキルは校正であって、書き直しではない。** 以下は触らない。

- 要約の言い回し・語順・長さの改善（読みやすくしようとしない）
- 記事の取捨選択、順番の入れ替え
- **URL の変更**（リンク先の正しさは判断できない。誤りに気づいたら直さず報告だけする）
- frontmatter の `date` / `title`、`<!-- categories: ... -->` の内容

# 注意

- 元の文が「誤りとまでは言えない」なら直さない。判断に迷ったものは**直さずに報告**する
- 1 ファイルずつ Edit する。まとめて `sed` で置換しない（同じ文字列が別の文脈にも出る）
