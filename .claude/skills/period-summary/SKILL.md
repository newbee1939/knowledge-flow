---

# 手順

1. **対象期間**: 引数（`YYYY-MM` または `YYYY`）。**引数がなければ前月**（JST の今日から 1 か月戻す）。さらにその前月が **12 月（＝実行日が 1 月）なら、続けて前年（`YYYY`）も**まとめる。
2. **材料を集める**: 対象期間のレポートの `title`（frontmatter）と各記事の H3 見出しだけを読む。本文まで読む必要はない。

    ```sh
    # 月: 2026-07 の場合（年は 2026-*.md にする）
    grep -h '^title:' docs/blog/posts/2026-07-*.md          # 日ごとのヘッドライン
    grep -h '^### ' docs/blog/posts/2026-07-*.md            # 記事の見出し
    ```

3. **サイト全体のタイトルを書く**: その期間を**ひとことで**言い表す。
    - **全角 30 文字以内**。年月の数字の横に並ぶため、長いと読みづらい
    - その期間に繰り返し現れた**大きな流れ**を書く。単発のニュースの寄せ集めにしない
    - 体言止め。「〜した月」「まとめ」のような説明的な語尾は付けない
    - 日次レポートと同じく、**専門用語は平易な言葉に開く**（[[daily-report]] の執筆方針に揃える）
    - 例: `オープンウェイト規制論争と、AIエージェント暴走の初事例`
4. **カテゴリごとのタイトルを書く**: カテゴリページ（`/categories/<slug>/`）の年月の横にも同じように並ぶ。
    - **対象は、その期間に記事が 5 件以上あるカテゴリだけ。** 数件しかないカテゴリは、カードのタイトルを見れば分かるので要らない
    - 各カテゴリの記事だけを見て書く。サイト全体のタイトルを流用しない（そのカテゴリの話として読めるか確認する）
    - カテゴリと期間の一覧・件数は次で取れる（H2 のジャンルも自動でカテゴリになる点に注意）

    ```sh
    grep -h -A1 '^### ' docs/blog/posts/2026-07-*.md | grep -o '<!-- categories: .* -->' \
      | sed 's/<!-- categories: //;s/ -->//' | tr ',' '\n' | sed 's/^ *//' | sort | uniq -c | sort -rn
    ```

5. **書き込み**: `docs/blog/summaries.json` の対象キーを追加または上書きする。
    - 期間のキーは月が `YYYY-MM`、年が `YYYY`。**期間キーは降順（新しいものが上）**、**カテゴリは名前順**に並べる
    - 他のキーは書き換えない。JSON として壊さない（末尾カンマ・コメント禁止）
6. **確認**: `npm test` が通ることを確かめる（JSON が壊れていれば落ちる）。
7. **commit**: `git add docs/ && git commit -m "summary: <期間>"`。

# データの形

```json
{
	"overall": {
		"2026": "年のひとこと",
		"2026-07": "月のひとこと"
	},
	"categories": {
		"AI Agent": {
			"2026-07": "AI Agent から見たその月のひとこと"
		}
	}
}
```

サイト側は `src/lib/summaries.ts` の `periodTitle()` でこのファイルを引き、トップページとカテゴリページの年・月ラベルの横に表示する。**キーが無い期間・カテゴリは何も表示されない**ため、書き込みに失敗しても表示は壊れない。

# 注意

- **期間が終わっていないうちは書かない。** 進行中の月・年をまとめても、あとで的外れになる
- **カテゴリ名は `docs/blog/posts/` のカテゴリコメントと 1 文字も違わないこと。** 表記がずれると引けず、黙って何も表示されない
- 書き込んでよいのは `docs/` 配下のみ。`src/` や `.github/` は変更しない
- 対象期間のレポートが 1 件も無ければ、何も書かずにその旨を報告して終わる
