# 手順

1. **対象期間**: 引数（`YYYY-MM` または `YYYY`）。**引数がなければ前月**（JST の今日から 1 か月戻す）。さらにその前月が **12 月（＝実行日が 1 月）なら、続けて前年（`YYYY`）も**まとめる。
2. **材料を集める**: 対象期間のレポートの `title`（frontmatter）と各記事の H3 見出しだけを読む。本文まで読む必要はない。

    ```sh
    # 月: 2026-07 の場合（年は 2026-*.md にする）
    grep -h '^title:' docs/blog/posts/2026-07-*.md          # 日ごとのヘッドライン
    grep -h '^### ' docs/blog/posts/2026-07-*.md            # 記事の見出し

    # 内部リンク用の索引（日付 / カテゴリ / タイトル / サイト内リンク の TSV）
    npm run articles | grep '^2026-07' > /tmp/kf-period.tsv
    ```

3. **サイト全体のタイトルを書く**: その期間を**ひとことで**言い表す。
    - **全角 30 文字以内**（半角は 0.5 文字で数える）。年月の数字の横に並ぶため、長いと読みづらい
    - その期間に繰り返し現れた**大きな流れ**を書く。単発のニュースの寄せ集めにしない
    - 体言止め。「〜した月」「まとめ」のような説明的な語尾は付けない
    - 日次レポートと同じく、**専門用語は平易な言葉に開く**（[[daily-report]] の「# 専門用語の開き方」に揃える）
    - 例: `オープンウェイト規制論争と、AIエージェント暴走の初事例`
4. **カテゴリごとのタイトルを書く**: カテゴリページ（`/categories/<slug>/`）の年月の横にも同じように並ぶ。
    - **対象は、その期間に記事が 2 件以上あるカテゴリだけ。** 1 件しかないカテゴリは、カードのタイトルを見れば分かるので要らない
    - 各カテゴリの記事だけを見て書く。サイト全体のタイトルを流用しない（そのカテゴリの話として読めるか確認する）
    - カテゴリと期間の一覧・件数は次で取れる（H2 のジャンルも自動でカテゴリになる点に注意）

    ```sh
    grep -h -A1 '^### ' docs/blog/posts/2026-07-*.md | grep -o '<!-- categories: .* -->' \
      | sed 's/<!-- categories: //;s/ -->//' | tr ',' '\n' | sed 's/^ *//' | sort | uniq -c | sort -rn
    ```

5. **書き込み**: `docs/blog/summaries.json` の対象キーを追加または上書きする。
    - 期間のキーは月が `YYYY-MM`、年が `YYYY`。**期間キーは降順（新しいものが上）**、**カテゴリはカテゴリ一覧ページと同じ名前順**（`localeCompare(name, 'en')`。`AWS` は `Anthropic` の後）に並べる
    - 他のキーは書き換えない。JSON として壊さない（末尾カンマ・コメント禁止）
6. **まとめ記事を書く**: `docs/blog/periods/<期間>.md`（月は `2026-08.md`、年は `2026.md`）。**同じ期間で再実行したら上書きする。**

    ```yaml
    ---
    date: 2026-08-01   # まとめた期間ではなく「書いた日」（JST の今日）
    title: "一行ヘッドライン"
    ---
    ```

    - **見出しは H2 だけ**を使い、その期間を貫くテーマで 4〜6 個に分ける。日ごと・ジャンル別の羅列にしない（それは日次レポートが既にやっている）
    - 各テーマ 2〜3 段落。「何が起きたか」を並べるだけでなく、**その月・年をあとから振り返って分かる形**（何が変わったのか）でまとめる
    - **専門用語は平易な言葉に開く**（[[daily-report]] の「# 専門用語の開き方」に揃える）。まとめは日次レポートより初めて読む人が多いため、その期間の軸になった用語ほど丁寧に開く
    - **書けるのは対象期間のレポートに書かれている事実だけ。** 数値・固有名詞・日付はレポートから引き写し、記憶や相場観で補わない。レポートに無い出来事は、覚えていても書かない（[[daily-report]] の「# ファクトチェック」と同じ理由）
    - **外部リンクと Mermaid 図は入れない。** 元記事の URL は日次レポートに残っている
    - **代わりにサイト内リンクを張る。** まとめの一文から、その話を詳しく書いた日次レポートへ降りられるようにする（「# 内部リンクの張り方」参照）
7. **確認**: `npm test && npm run build` が通ることを確かめる（JSON が壊れていれば落ち、ファイル名が期間キーでなければビルドが止まる）。あわせて、**本文の数値・固有名詞を対象期間のレポートで 1 つずつ grep して裏を取り**、張った内部リンクが索引に実在するかを確かめる（**リンク先がズレても切れずに記事の先頭へ着地するため、目視では気づけない**）。

    ```sh
    grep -o '(/blog/[^)]*)' docs/blog/periods/2026-07.md | tr -d '()' | sort -u \
      | while read -r link; do grep -qF "$link" /tmp/kf-period.tsv || echo "索引に無い: $link"; done

    # 年のまとめだけ: 張った先のまとめ記事が実在するか（無ければ 404 になる）
    grep -o '(/periods/[^)]*)' docs/blog/periods/2026.md | tr -d '()' | sed 's|/periods/||;s|/$||' | sort -u \
      | while read -r key; do [ -f "docs/blog/periods/$key.md" ] || echo "まとめが無い: $key"; done
    ```
8. **commit**: `git add docs/ && git commit -m "summary: <期間>"`。

# 内部リンクの張り方

まとめ記事はその期間の上澄みなので、**一文ごとの出どころである日次レポートへ辿れるようにする**。「もっと詳しく」と思った読者が、検索し直さずに元のレポートへ降りられるのが目的。

リンクは **`/blog/…` `/periods/…` から書く**（`/knowledge-flow/…` と書かない）。公開先の接頭辞はビルド時に付く。

## 日次レポートへ（月・年に共通）

材料は手順 2 で作った索引（`/tmp/kf-period.tsv`）。4 列目がそのまま貼れるサイト内リンク（`/blog/<日付>/#<アンカー>`）。年のまとめも同じように日次レポートへ張る（索引はその年 12 か月ぶんになる）。

```markdown
7月の話題の中心は、中国発の[Kimi K3](/blog/2026-07-18/#中国製aikimi-k3がgpt-56に匹敵するモデルとして登場)だった。
```

- **リンクは索引の 4 列目をコピーする。手で組み立てない**（アンカーはサイト本体と同じ関数で算出している。自分で組むと記号や重複見出しの扱いでズレるうえ、ズレてもリンクは切れず記事の先頭に着地するため、後から気づけない）
- **各 H2 セクションに 2〜4 本が目安。** そのテーマの軸になった出来事に張る。上限ではないが、1 段落にいくつも並べると本文が読めなくなる
- **同じ記事へ、1 つのまとめ記事の中で 2 回張らない**
- リンクテキストは文中の自然な語（プロダクト名・出来事の呼び名）でよい。記事タイトルをそのまま貼って文を崩さない
- 具体的な数字・固有名詞・調査結果を挙げた箇所を優先する。伝聞のまま置かれた事実ほど、出どころへ飛べる価値が高い
- 索引に無い話題（その期間のレポートに書いていないこと）には張らない

## まとめ記事どうし（年のまとめに追加で）

- **年のまとめは、日次レポートに加えて、その年の月のまとめへも張る**（`/periods/2026-07/`。`ls docs/blog/periods/` にある期間だけ。無い期間へ張ると 404 になる）。各テーマで最初にその月に触れた箇所に 1 本
- **まとめ記事へは、ページ先頭に張る（`#見出し` を付けない）。** 索引が持っているのは日次レポートのアンカーだけなので、まとめ記事のアンカーは手で組むことになり、ズレても記事の先頭に着地して気づけない

# データの形

まとめ記事は `docs/blog/periods/<期間>.md`。**ファイル名がそのまま URL（`/periods/2026-08/`）になり、年表の年・月ラベルからのリンク先の照合キーになる**ため、期間キー以外の名前を付けるとビルドが止まる。トップページは `date` が最新レポートと同じ日の間だけ「2026年8月まとめ」のリンクを出し、それ以降は年表の年・月ラベルから辿れる。

ひとことタイトルは `docs/blog/summaries.json`。

```json
{
	"overall": {
		"2026": "年のひとこと",
		"2026-07": "月のひとこと"
	},
	"categories": {
		"AI Agent": {
			"2026-07": "AI Agent から見たその月のひとこと"
		}
	}
}
```

サイト側は `src/lib/summaries.ts` の `periodTitle()` でこのファイルを引き、トップページとカテゴリページの年・月ラベルの横に表示する。**キーが無い期間・カテゴリは何も表示されない**ため、書き込みに失敗しても表示は壊れない。

# 注意

- **期間が終わっていないうちは書かない。** 進行中の月・年をまとめても、あとで的外れになる
- **カテゴリ名は `docs/blog/posts/` のカテゴリコメントと 1 文字も違わないこと。** 表記がずれると引けず、黙って何も表示されない
- 書き込んでよいのは `docs/` 配下のみ。`src/` や `.github/` は変更しない
- 対象期間のレポートが 1 件も無ければ、何も書かずにその旨を報告して終わる
