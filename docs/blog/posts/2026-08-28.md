### [How we saved 100 terabytes of memory by optimizing 1.1.1.1's DNS cache](https://blog.cloudflare.com/dns-cache-memory-optimization-1111/)
<!-- categories: Cloudflare, DNS, Performance -->

Cloudflareが公式ブログで、パブリックDNS「1.1.1.1」を支えるキャッシュ基盤のメモリ削減を詳しく解説している。常時2500億件超のDNSキャッシュを抱えているため、1件あたり数十バイトの無駄が全体では途方もない量になる。取った手は5つで、可変長のまま持っていたRustの`Vec`/`String`を伸縮しない`Box`に置き換えて余剰確保をなくす（1件あたり64バイト減）、3つに分かれていた応答レコードの配列を1本にまとめてポインタを2バイトのオフセットに変える（同28バイト減）、問い合わせ名と同じ場合はレコードの所有者名を省く、大きい列挙型を箱に包んでA/AAAAのような小さなレコードの余白を削る、そして解析済みの構造体ではなく受信したままのバイト列で保持する、というものだ。結果として1件あたりの占有量は953バイトから420バイトへ56％減り、全サーバー合計で約100テラバイトのメモリが空いた。副産物として書き込み性能が43％向上し、参照の待ち時間も19％短くなっている。

### [Float Bloat: vector serialization gone wrong](https://bonsai.io/blog/float-bloat/)
<!-- categories: Performance, Database -->

Bonsaiの技術ブログが、埋め込みベクトル（文章の意味を数百個の数値の並びで表したもの）をJSONでやり取りするときに起きている無駄を指摘している。埋め込みモデルの出力はほぼ32ビット浮動小数点なのに、多くのクライアントライブラリがJSON化の際に64ビットへ広げてしまい、元データには存在しない桁が文字列として付いてくる。32ビットの有効桁は9桁、64ビットは17桁なので、値1つにつき8バイト前後が意味のない情報で埋まる計算だ。768次元のベクトル1000万件で試すと、広がったJSONは151.8GB、適切な桁で書き出すと86GBとなり、65.8GBが桁の水増しだけで消えている。対策は、Pythonの`%.9g`やJavaScriptの`toPrecision(9)`のように本来の精度で書き出すか、base64やArrow、Protobufといったバイナリ形式に切り替えるかで、いずれも情報を落とさずにテキストで約43％、バイナリで約80％減らせるとしている。

### [Integer Divide-by-Zero in `vpk_read_packet` (VPK Demuxer)](https://code.ffmpeg.org/FFmpeg/FFmpeg/issues/24290)
<!-- categories: Security, Testing -->

FFmpegに報告された、Sony PS2向けVPK形式の読み込み処理でゼロ除算が起きる不具合。`libavformat/vpk.c`の`vpk_read_packet`が、チャンネル数が0かどうかを確認せずに除算しているため、チャンネル数を0にしたVPKファイルを読ませるとSIGFPEでプロセスが落ちる。報告者は自作のファザー（でたらめな入力を大量に投げて異常を探すツール）で見つけており、13188件の種データから49万5211回の実行で到達したと書いている。再現用に添えられたファイルはわずか21バイトで、VPKの識別子は正しくチャンネル数の欄だけが0になっている。任意コード実行ではなくサービス停止どまりだが、外部から来たファイルを解析する用途では実害が出る種類のもので、報告時点でメンテナーからの返答は付いていない。

### [「ただのファイル属性」がroot権限に化ける　Linux ntfs3に潜んだ権限昇格のわな](https://atmarkit.itmedia.co.jp/ait/articles/2608/27/news038.html)
<!-- categories: Linux, Security -->

＠ITが、LinuxカーネルのNTFSドライバ「ntfs3」で見つかった権限昇格の問題を解説している。ntfs3はWSL（Windows上でLinuxを動かす仕組み）向けに`$LXUID`／`$LXGID`／`$LXMOD`という拡張属性を読み込むが、`$LXMOD`の値をファイルの権限へ反映する際にSUID／SGIDビットを落としていなかった。そのため、細工したNTFSイメージを一般ユーザーがマウントすると、その中の実行ファイルがrootとして動いてしまう。USBメモリを挿すだけで条件が揃う類のもので、対策としては、NTFSパーティションを`nosuid`オプション付きでマウントすることが挙げられている。Ubuntu、Debian、Fedora、RHEL、SUSE、Arch Linuxなど広い範囲が対象で、外部メディアを自動マウントする設定にしている環境ほど影響を受けやすい。
