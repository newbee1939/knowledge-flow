### [Probing DNS at Cloudflare](https://blog.cloudflare.com/probing-dns-at-cloudflare)

### [NVIDIA RTX Sparkの暗号化ファームウェアにより、AC電源接続時にLinux上での推論速度が35％低下](https://gigazine.net/news/20261123-linux-nvidia-rtx-spark-laptop)
<!-- categories: NVIDIA, Linux, Hardware -->

RTX Spark を積んだノートPCで Linux を使うと、電源につないだときだけAIの処理が大きく遅くなる。Gigazine によると、計測では電源接続時の生成速度がバッテリー駆動時の4分の1ほどに落ちた。原因は、CPU と GPU の電力配分を決める Windows 専用の部品にある。その設定表が暗号化され、Linux から読めないのだ。根本的には NVIDIA の対応が要り、当面は Windows 上で Linux を動かす WSL が回避策になる。

### [S3 汎用バケットの GET/HEAD が 11,000 リクエスト/秒に引き上げられたので、Go で 17,000 リクエスト/秒を流してみた](https://dev.classmethod.jp/articles/amazon-s3-increased-read-request-rate)
<!-- categories: AWS, Performance -->

Amazon S3 で、ファイルの読み出しにかかる処理能力の目安が2倍の毎秒11,000回に上がった。上限は、ファイル名の先頭部分（プレフィックス）ごとにかかる。DevelopersIO の筆者は、1つのプレフィックスに集中して負荷をかけた。毎秒17,000回まで上げても、エラーは1件も出なかった。書き込みや削除の上限は毎秒3,500回のままなので、読み出しが多い用途ほど恩恵が大きい。

### [Mutex poisoning is not for everyone](https://bertptrs.nl/2026/11/16/mutex-poisoning-is-not-for-everyone.html)
<!-- categories: Rust -->

Rust の Mutex（同じデータを同時に触らせないための鍵）の「毒化」は、標準にすべきでないと著者は論じる。毒化とは、鍵を持ったまま処理が異常終了すると、その後の利用者にエラーを返す仕組みだ。著者は、まれな場面のために鍵を使う全箇所でコードが膨らみ、速さも落ちると指摘する。毒化しない Mutex は試験版にしかなく、まずそれを正式な機能にすべきだと提案している。

<!-- categories: Database, AWS, Distributed Systems -->

SRE の経験がないまま SRE 組織のマネージャーになった発表者が、その経緯をマネーフォワードの発表資料で語った。発表者は、意見を言えない、Google の SRE 本の水準に圧倒される、何でも引き受けてしまう、という落とし穴を挙げる。技術の判断はメンバーに任せ、目的の言語化や優先順位づけ、役割分担の明確化に集中したという。マネージャーに求められたのは技術力より、チームが自分で強くなれる環境づくりだったと結論づけている。
