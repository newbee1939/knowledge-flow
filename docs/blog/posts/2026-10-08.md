### [Twenty-two pending curl vulnerabilities](https://daniel.haxx.se/blog/2026/10/07/twenty-two-pending-curl-vulnerabilities)
<!-- categories: Security, OSS -->

curl の開発チームが、10月14日に脆弱性22件をまとめて直す新版を出すと予告した。作者のブログによると、うち1件は深刻度「高」で、2021年以降この評価は2件しか出ていなかった。この1件が見つかったため、リリースを予定より数週間前倒しした。詳細は公開日まで伏せられるため、curl を組み込んだ製品の管理者は当日の更新に備えたい。

### [How fast is Python 3.15?](https://blog.miguelgrinberg.com/post/how-fast-is-python-3-15)
<!-- categories: Python, Performance -->

Python 3.15 の正式版を前に、過去の版と速度を比べた結果を著者が公開した。再帰とループの2種類の小さなプログラムで、3.10 以降の各版を測っている。実験段階の JIT（実行中に機械語へ変換して速くする仕組み）を除けば、目立った伸びはなかった。著者は速度目当てで急いで上げる必要はなく、新しい文法などを使いたいかで決めればよいとしている。

### [On Git Refs](https://matklad.github.io/2026/10/07/git-ref.html)
<!-- categories: Git -->

Git の「ref（参照）」という仕組みを整理し直した記事を、著者が公開した。Git は中身から名前が決まる書き換え不能な保存庫に加え、名前とコミットを結ぶ書き換え可能な対応表を持つ。ブランチもタグもこの対応表の1項目にすぎないと分かると、挙動が見通しやすくなる。`origin master` と `origin/master` の書き分けのような、日頃のつまずきがほどける内容だ。

### [Zeroization, part 1: Wiping can make things worse](https://00f.net/2026/10/06/zeroization-1)
<!-- categories: Security, C -->

秘密鍵などを使い終わってゼロで消す処理が、かえって秘密の写しを増やす場合があると著者が示した。コンパイラは不要と判断した消去を削ってしまい、無理に消させると元はレジスタにしかなかった値がメモリへ書き出される。こうしてできた写しは、消去の後も残ってしまう。AIが機械的に勧めがちな修正だけに、実際に出力される機械語で確かめるべきだという。

### [C for Rust Programmers](https://bd103.dev/blog/2026-10-07-c-for-rust-programmers)
<!-- categories: C, Rust -->

Rust からプログラミングを始めた著者が、C を学んで驚いた点をまとめた。たとえば C の真偽値は長く言語の基本型ではなく、0と1の定義で代用されてきた。文字列も長さを持たず、末尾の0で終わりを示すなど、Rust の前提が通じない場面を挙げる。「C から Rust へ」の解説は多いが逆向きは珍しく、Rust 世代が古いコードを読む手引きになる。
