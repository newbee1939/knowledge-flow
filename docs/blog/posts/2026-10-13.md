## AI

### [Muse Wonder: A Frontier Model For Personal & Professional AI Agents](https://research.meta.ai/blog/muse-wonder)
<!-- categories: Meta, LLM, AI Agent -->

Meta が、自社で最も高性能なAIモデル「Muse Wonder」と上位版「Muse Wonder Full」を公開した。Meta の発表によると、売りは2つの能力だ。1つは利用者の事情を会話をまたいで覚えておく力、もう1つは行き詰まっても別の手を試し続ける粘り強さである。開発者向けAPIとコーディング用サービスで今日から使え、AIエージェント「Muse」にも順次載る。[MetaのAIエージェント「Muse」の公開](/blog/2026-09-09/#meta-debuts-its-muse-ai-agent-will-consumers-trust-it)から約1カ月で、その頭脳が最前線級に入れ替わることになる。

### [AI models may be capable of self-replicating without access to a datacenter](https://www.anthropic.com/research/self-replicating-ai)
<!-- categories: Anthropic, Security, LLM -->

小型のAIモデルが、家電などのネット機器に自分をコピーして広がれる日が近いと Anthropic が警告した。同社の研究チームは、約55ドルの安価なTVボックス15台をつなぎ、1つのAIモデルを分担して動かしてみせた。90億パラメータ級のモデルでも、試した9種類の機器のうち8種類で自力でAIを動かす準備を整えられたという。中心となるサーバーを持たないため、こうした「AIワーム」は止めにくいと指摘している。

### [CLI: make `daemon_auto_start` opt-in — a persistent, self-updating background daemon shouldn't be the default](https://github.com/openai/codex/issues/48195)
<!-- categories: OpenAI, Security, AI Agent -->

OpenAI のコーディングAI「Codex」のCLI版が、裏で常駐プログラムを勝手に動かしていると問題になった。GitHub の Issue で利用者が指摘したものだ。画面を閉じても常駐し続け、約374MBの本体をコピーして1時間ごとに自己更新する。最初に起動した端末のプロキシ設定を握り続けるなど、利用者の意図と違う動きも報告されている。自分で入れたツールが知らない間に別物へ入れ替わる設計は、企業での利用では見過ごしにくい。

### [各社のAIがリリース後にどれだけ性能変化したかがグラフでわかるベンチマーク「Nerf Bench」](https://gigazine.net/news/20261013-nerf-bench)
<!-- categories: LLM, Testing -->

AIモデルが公開後にこっそり劣化していないかを追う評価サイト「Nerf Bench」を、Gigazine が紹介した。公開日の成績を100%とし、同じテストを繰り返して上下を記録する。正答率だけでなく、使った文字数や費用が増えた場合も「性能低下」と数える。テスト内容は不正防止のため非公開だが、「最近AIが劣化した」という体感を数字で確かめる手がかりになる。

### [Announcing AWS Lambda Web Functions | Amazon Web Services](https://aws.amazon.com/blogs/aws/announcing-aws-lambda-web-functions-for-fast-consistent-web-app-performance-anywhere)
<!-- categories: AWS -->

AWS が、普通の Web アプリを Lambda で動かせる「Lambda Web Functions」を公式ブログで発表した。Express や Next.js で書いたサーバーを、Lambda 専用の形に書き直さずに載せられる。1つの実行環境で最大128件のリクエストを同時にさばき、CPU は実際に使った時間だけ課金される。[公開前にソースから読み解かれていた](/blog/2026-10-04/#リリース前のaws-lambda-web-functionslambda-webの仕組みを公開ソースから読み解いてみた)サービスが、東京リージョンを含めて正式に使えるようになった。

### [How I Found a $90,000 Remote Code Execution Vulnerability in Google](https://simonkoeck.com/writeups/google-devsite-flask-session-pickle-rce)
<!-- categories: Google, Security, Python -->

Google の開発者向けドキュメントサイトで、外から任意のコードを実行できる欠陥が見つかり、9万ドルの報奨金が出た。発見者の解説によると、ログイン用の Cookie に、署名用の秘密鍵そのものが入っていた。そのため Cookie を偽造でき、サーバーが中身を Python のオブジェクトとして復元する際にコードが動いた。秘密の使い回しと危険な復元処理が重なると大事故になる、という教訓だ。

### [(Post-Quantum) Cryptographic Right Answers](https://words.filippo.io/right-answers)
<!-- categories: Security, Standards -->

暗号の専門家 Filippo Valsorda が、開発者向けに「今選ぶべき暗号方式」の一覧を量子計算機時代に合わせて更新した。著者によると、量子計算機への移行は2029年までに終える必要があるという合意ができつつある。共通鍵の暗号はそのままでよいが、鍵交換や電子署名は耐量子の方式へ総入れ替えになる。「手に入る最良のAIにレビューさせる」ことも、新たに正解の1つに加えている。

### [Parsing JSON at tens of gigabytes per second… in Python](https://lemire.me/blog/2026/10/12/parsing-json-at-tens-of-gigabytes-per-second-in-python)
<!-- categories: Python, Performance -->

Python で JSON を毎秒66GBの速さで読み込めたと、研究者の Daniel Lemire がブログで報告した。決め手は、GIL（同時に1つのスレッドしか動けない制約）を外した Python 3.14 と、64コアの並列処理だ。実際に読む値だけを Python のデータに変える工夫で、同じ64スレッドの標準ライブラリの約20倍に達した。Python は遅いという前提が、大量データ処理でも崩れつつある。

### [A modern web app in c](https://prophitt.me/writing/a-modern-web-app-in-c)
<!-- categories: C, SQLite -->

決済やメール送信まで備えた商用 Web サービスを、C言語と1994年流の CGI で作った体験談だ。著者によると、リクエストごとにプログラムを起動し、データは SQLite のファイル1つに置いている。フレームワークもコンテナも使わず、更新はファイルを1つ差し替えるだけで済む。仕組みが頭に収まる小ささは、複雑になりがちな今の Web 開発への問いかけになっている。

### [Making big downloads resumable in firefox](https://lunarwatcher.codeberg.page/til/firefox/resumable-big-downloads.html)
