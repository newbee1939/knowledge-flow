### [Claude Code の blockReadsOutsideWorkingDirectories で作業ディレクトリ外の読み取りを拒否してみた](https://dev.classmethod.jp/articles/claude-code-block-reads-outside-working-directories)
<!-- categories: Claude Code, Security -->

Claude Code に加わった「作業フォルダの外を読ませない」設定の効き方を、DevelopersIO が検証した。オンにすると、権限モードに関係なくファイル読み取りや検索のツールが外側のパスを拒否する。ただし Bash 経由だと、サンドボックス（OS がコマンドの操作範囲を囲う仕組み）が無効なら承認で読めてしまう。作業外のファイルを確実に守るには、サンドボックスとの併用が前提になる。

### [gVisor is being donated to CNCF](https://gvisor.dev/blog/2026/10/02/gvisor-cncf)
<!-- categories: CNCF, Security, OSS -->

Google が、コンテナを安全に隔離する gVisor を CNCF（Kubernetes などを預かる中立団体）へ寄贈する。gVisor の公式ブログによると、今後数週間で Google 以外の保守担当者にも権限を渡していく。背景には、Google 単独の持ち物だったせいで Linux 側に性能改善の修正を断られた経緯がある。Kubernetes と同じ道をたどり、利用する企業の裾野を広げる狙いだ。

### [Cloudflare OHTTP gateway](https://blog.cloudflare.com/announcing-cloudflare-ohttp-gateway)
<!-- categories: Cloudflare, Privacy, HTTP -->

Cloudflare が、利用者の IP アドレスをアプリに見せない「OHTTP Gateway」の限定ベータを始めた。公式ブログによると、OHTTP は中継役と復号役を別々の事業者に分ける IETF の標準だ。どちらか一方だけでは「誰が」と「何を」を同時に知れないため、匿名性が保たれる。これまで復号役は自前で運用する必要があり、その手間を肩代わりする製品になる。

### [Kubernetesノードが物理障害でNotReadyになってからPodが再スケジュールされるまで](https://qiita.com/yosshi_/items/7ed4f99fbe9b96e360e3)
<!-- categories: Kubernetes, SRE -->

Kubernetes のノードが壊れてから、Pod が別の場所で動き直すまでの流れをソースから追った Qiita の記事。初期設定では異常の判定に約50秒、Pod の退避開始までさらに300秒かかる。Kubernetes は「ノードが止まった」のか「通信が切れただけ」なのかを区別できないためだ。特に StatefulSet（データを持つアプリ向けの管理単位）は、人が印を付けるまで自動では復旧しない。

### [【React】「1つのuseEffect内でrefを立てる」useUpdateEffectはStrictModeで壊れる](https://qiita.com/shun123/items/b7a01b3d7379274d3ebc)
<!-- categories: React -->

「初回は動かさず、値が変わったときだけ動く」React の自作フックが壊れる理由を、Qiita の記事が解説した。開発時の StrictMode は点検のため、部品の取り外しと付け直しを1回まねる。このとき目印の値が残ったままになり、付け直しを「更新」と取り違えて初回に処理が走る。記事は処理を2つに分けて直す方法を、実際の動作ログ付きで示している。
