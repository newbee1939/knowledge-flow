### [WordPress: Unauthenticated path traversal leading to conditional RCE](https://github.com/WordPress/wordpress-develop/security/advisories/GHSA-7hp8-65ch-5whp)
<!-- categories: WordPress, Security, PHP -->

WordPress に、ログインなしで任意のコードを実行されうる最大深刻度の欠陥が公開された。公式の勧告によると、ページ用テンプレートを探す処理が、テーマの外にあるPHPファイルまで読み込んでしまう。有効なテーマに`page-`で始まるディレクトリがあるなど条件は付くが、成立すればサイトを乗っ取られる。修正は7.1.2で入り、7月の[WordPressに認証不要でコードを実行される緊急脆弱性、即時更新を](/blog/2026-07-22/#wordpressに認証不要でコードを実行される緊急脆弱性即時更新を)に続いて認証前の入口が突かれた形だ。

### [SAML: A Fractal of Bad Design](https://blog.trailofbits.com/2026/09/21/saml-a-fractal-of-bad-design)
<!-- categories: Security, Standards, OAuth -->

シングルサインオン（一度の認証で社内の複数サービスに入れる仕組み）の古い規格SAMLは、もう捨てるべきだという主張が公開された。Trail of Bits によると、SAMLはXMLを土台にしており、署名を検証する前の「同じ形に揃える」処理で取り違えが起きやすい。署名がデータの内部に埋め込まれるため、受け取ったバイト列をそのまま検証できないのも弱点だという。同じことができるOIDCは署名を切り離しているので、新規の導入はOIDCにすべきだと結論づけている。

### [Looking forward to Git 2.56 - and 3.0](https://lwn.net/SubscriberLink/1094575/2385e98583715c2b)
<!-- categories: Git, Rust, OSS -->

Git が9月末に2.56を出し、その先の3.0で土台を大きく変える見通しだ。LWN.net によると、3.0では既定のハッシュがSHA-1からSHA-256へ、参照の保存形式がファイルの集まりから二進の`reftable`へ変わる。ビルドにRustのコンパイラが必須になるため、Rustが動かない環境は2.99のLTSで足止めになる。2.56自体には、履歴から特定のコミットを取り除く`git history drop`などが入る。

### [We just shipped support for the ugliest part of HTTP: Vary](https://blog.cloudflare.com/vary-support)
<!-- categories: Cloudflare, HTTP, Performance -->

Cloudflare が、HTTPの`Vary`ヘッダーをキャッシュ規則で扱えるようにした。公式ブログによると、`Vary`は「同じURLでも要求の内容次第で返すものが変わる」とキャッシュ側へ伝える仕組みだ。ただし「どこまで違えば別物か」は伝わらないため、素直に受け取るとキャッシュが細かく割れて当たらなくなる。今回は値を揃える・そのまま使う・キャッシュしないの3つを項目ごとに選べるようにして、この割れ方を抑えている。

### [[Welcome to AWS 企画] DuckDB v2.0 alpha のクライアント/サーバー構成（quack ＋ CONNECT）で Amazon S3 Tables を試してみた](https://dev.classmethod.jp/articles/20260922-duckdb-v20-alpha-quack)
<!-- categories: DuckDB, Database, AWS -->

手元で動く分析用データベースDuckDBを、クライアントとサーバーに分けて使う試みが報告された。DevelopersIO によると、[A Preview of DuckDB v2.0](/blog/2026-08-18/#a-preview-of-duckdb-v20)で予告された`quack`拡張と`CONNECT`文で、S3上のテーブルを作って書き込めたという。`CONNECT`は接続先を足すのではなく実行の場所ごとサーバー側へ移すため、手元のテーブルは見えなくなる。クライアントにAWSの認証情報を置かずに済む反面、認可の既定がなく本番には作り込みが要ると指摘している。
