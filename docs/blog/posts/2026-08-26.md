### [Metaが100万GPU規模を想定した新通信プロトコル「MetaRoCE」を発表、パケットロスを前提にEthernetでAIクラスタを高速接続](https://gigazine.net/news/20260825-meta-rdma-protocol-metaroce/)
<!-- categories: Meta, Network, Datacenter -->

GIGAZINEが伝えたところでは、MetaがAIクラスタ向けの新しい通信規格「MetaRoCE」を発表した。従来のRoCEv2は、GPU同士がメモリを直接やり取りするRDMA（相手のCPUを介さずにメモリへ書き込む高速通信）を成立させるため、パケットが落ちたり順番が入れ替わったりしないことを前提に組まれており、規模が大きくなるほどその前提が崩れて性能が落ちていた。MetaRoCEはそこを逆転させ、パケットが落ちることも順番が入れ替わることも当たり前に起きる前提で設計されている。具体的には、順不同のまま受け取って置く仕組み、複数経路への同時分散、256ビットの確認応答ベクタを使って落ちた分だけ再送する方式を組み合わせており、パケットロス1％でも約86％のスループットを維持し、10％でも動き続けたと報告されている。仕様はOpen Compute Projectを通じて公開され、10月のOCP Global Summitで参照実装と試験環境を出す計画で、AMD PensandoのNICはすでに対応済みだという。

### [Hunting Down a Go Runtime Bug on 32-bit Embedded Systems](https://sigma-star.at/blog/2026/08/go-runtime-netpoll-bug/)
<!-- categories: Go -->

sigma starのエンジニアが、32ビット環境で長時間動かしたGoのプログラムが `runtime: netpoll: eventfd ready for something unexpected` で落ちる問題を追いかけた記録を公開している。原因はGoランタイム内部のポインタの取り違えだった。Goはイベント通知の受け口を表す生ポインタと、タグを付けたポインタの2種類を同じ8バイトの領域に入れているが、32ビット環境ではタグに使う通し番号が生ポインタのアドレスと同じ下位4バイトに重なる。オブジェクトの再利用が数百万回続くうち、その通し番号がたまたま生ポインタの値と一致してしまい、ランタイムがソケットをイベント通知用の口だと誤認する、という筋書きだ。修正は生ポインタを置くのをやめ、タグ付きの空ポインタに統一するもので、すでに本体へ取り込まれている。踏むまでに数百万回の再利用が要るため、テストでは出ず本番の長時間稼働でだけ現れる種類の不具合になっている。

### [Replacing a Rust Enum with a 64-bit Word Made My Interpreter 17% Faster](https://pointersgonewild.com/2026-08-25-replacing-a-rust-enum-with-a-64-bit-word/)
<!-- categories: Rust, Performance -->

### [40001 is not a query error](https://dev.to/mohamedaboelmagd/40001-is-not-a-query-error-2497)
<!-- categories: PostgreSQL, Database -->

PostgreSQLで最も厳しい分離レベル（SERIALIZABLE）を使うと、同時に走った処理が矛盾しうると判断された時点でエラー40001が返る。著者が指摘しているのは、これを「そのSQLが失敗した」と読んで同じクエリだけ再実行する実装が多い、という点だ。実際にはこのエラーはトランザクション全体を巻き戻すので、同じ接続で次に何を投げても別のエラー（25P02）が返るだけで前に進まない。正しい対処はトランザクションの境界ごとやり直すことで、記事はあわせて、メール送信や外部API呼び出しのようにロールバックで取り消せない処理はコミット後に回すこと、再試行の待ち時間には完全なジッターを入れて再衝突を避けること、アクセスするレコードが読めるなら `FOR UPDATE` で順番に鍵を取るほうが再試行より速いことを挙げている。

GIGAZINEが伝えたところでは、『メタルギアオンライン』のバージョン1.1.2.8に、ロビーに参加しただけで任意のコードを実行されうる脆弱性（CVE-2026-19874）が見つかった。原因は、退出させられたプレイヤー数を保持する `kick_num` という値の検証漏れで、確保した領域を越えて書き込めてしまい、プログラムの流れを決めるデータを上書きできる状態だった（ヒープバッファオーバーフロー）。厄介なのは、不正改造対策として組み込まれているDenuvoが、読み書きと実行の両方が許された領域を作ってしまっており、そこが攻撃コードの置き場になった点だ。セキュリティ研究者のAlieche Checkett氏が7月15日にKonamiへ報告し、8月24日に公開された。Konamiはバージョン1.1.2.9で修正済みで、古いバージョンはオンラインに接続できないようになっている。
