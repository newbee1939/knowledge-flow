### [Bloom Security Found a Supply-Chain Vulnerability Exposing 1,500 npm Packages to Malicious Takeover](https://hackernoon.com/bloom-security-found-a-supply-chain-vulnerability-exposing-1500-npm-packages-to-malicious-takeover?source=rss)
<!-- categories: npm, Supply Chain, GitHub Actions -->

npm の「Trusted Publishing」（GitHub から鍵なしで公開する仕組み）に穴があったと HackerNoon が報じた。発見した Bloom Security によると、npm は公開元を「持ち主/リポジトリ名」の名前だけで識別していた。名前が空いた後に他人が同じ名前を取ると、正規の版として公開できてしまう。対象は1500超のパッケージで、npm は修正済みだが、紐付け設定の見直しが勧められている。

### [struct's lifetime requirements can be bypassed via covariant field assignment](https://github.com/rust-lang/rust/issues/164250)
<!-- categories: Rust -->

Rust のコンパイラが、使い終わったメモリを参照するコードを見逃す不具合が報告された。Rust の型を担当するチームによると、この穴は11年前から存在していたという。悪用するには意図的に細工した後片付け処理（Drop）が要り、偶然踏んでいる可能性は低いと説明している。「コンパイルが通れば安全」という Rust の前提に関わるため、優先度高として扱われている。

### [第281回　MySQL 26.7で変わったAUTO_INCREMENTのカウンター保存](https://gihyo.jp/article/2026/10/mysql-rcn0281)
<!-- categories: MySQL, Database -->

MySQL 26.7 で、自動連番 AUTO_INCREMENT の番号を先にまとめて確保する動きが標準になった。gihyo.jp の連載によると、既定では50個先まで確保し、番号を保存する回数を減らして速くする。その代わり、サーバーが異常終了すると予約した分が飛ばされ、欠番が出ることがある。連番に抜けがないことを前提にした処理は、新しい設定値を確認しておきたい。

### [A plea not to use uv-build](https://blogs.gentoo.org/mgorny/2026/10/12/a-plea-not-to-use-uv-build)
<!-- categories: Python, Rust, OSS -->

Gentoo Linux の開発者が、Python パッケージ作りに「uv-build」を使わないでとブログで訴えた。著者によると、uv-build は Rust 製で大きく、更新も頻繁なため、利用者が何度も一から作り直すことになる。Rust が動かない環境では、パッケージ自体が使えなくなる恐れもある。純粋な Python 製の軽い代替で十分で、速さの差もわずかだと著者は述べる。
