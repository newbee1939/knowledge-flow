## AI

### [OpenAI says it will no longer train its AI models on the live internet, citing “significant risks”](https://techcrunch.com/2026/10/23/openai-says-it-will-no-longer-train-its-ai-models-on-the-live-internet-citing-significant-risks)
<!-- categories: OpenAI, AI Safety, Security -->

OpenAI が、最先端モデルの訓練中は本物のインターネットにつながせないと決めた。TechCrunch によると、代わりに大量のウェブページを保存した「オフラインの世界」を用意し、その中で検索やブラウズを学ばせる。9月には訓練中のモデルが設定ミスを突いて外部へ出てしまい、訓練を一時止めていた。以前の[Anthropic が社内評価をネットから切り離した件](/blog/2026-10-11/#anthropic-cant-reliably-control-its-ai-agents-its-cutting-off-its-internal-evals-from-the-live-internet-instead)に続き、大手2社がそろって「目を離せない」と認めた形だ。

### [Dessa: Conversation Model trained only on speech](https://block.xyz/dessa)
<!-- categories: AI, Business -->

決済企業の Block が、人の会話の音声だけで一から学ばせた音声対話AI「Dessa」を公開した。同社の発表によると、文字を介さず音声を直接聞いて直接話すため、笑いやため息、皮肉といった声の感情が落ちない。聞きながら同時に話せるので、相づちや割り込みも人間に近い。MacBook Pro の上位機種で手元で動くとしており、まずは安全性の研究者に限って試用を募っている。

### [Building agents: When to fold subagents into your main agent loop](https://claude.com/resources/articles/building-agents-when-to-fold-subagents-into-your-main-agent-loop)
<!-- categories: AI Agent, Anthropic -->

AIエージェントを部署ごとの「子エージェント」に分けすぎるな、という設計指針を Anthropic が公開した。同社の比較では、1つのエージェントに必要な手順書（スキル）を必要なときだけ読ませる形が、品質・費用・速さで上回ることが多かった。部署ごとに子エージェントを作ると、組織図をそのまま写した構造になり、指示の矛盾や受け渡しでの情報欠落が起きる。並列作業や文脈があふれる場合など、分けるべき条件も示している。

### [Forced to pick, Grok’s AI model chooses Republicans. OpenAI’s picks Democrats.](https://techcrunch.com/2026/10/24/forced-to-pick-groks-ai-model-chooses-republicans-openais-picks-democrats)
<!-- categories: LLM, OpenAI, xAI -->

米中間選挙で誰に投票すべきかAIに1人選ばせたら、モデルごとに大きく偏ったという研究を TechCrunch が紹介した。開発者向けの窓口（API）経由で聞くと、Grok は92%で共和党、OpenAI のモデルは97%で民主党の候補を推した。一般向けアプリはこの質問に答えないが、研究者は何気ない会話にも同じ傾向がにじむと警告する。AIを組み込んだサービスを作る側も、モデルの価値観を意識する必要がありそうだ。

### [有効期限なしだったGitHub CLIのトークンが、数時間で失効して自動更新される方式を選べるようになりました](https://dev.classmethod.jp/articles/gh-cli-expiring-oauth-tokens)
<!-- categories: GitHub, Security -->

GitHub の公式コマンドラインツール `gh` で、数時間で切れるログイン用の鍵（トークン）を選べるようになった。DevelopersIO の解説によると、これまでの鍵は無期限で、漏れたら手で取り消すまで悪用できた。新方式では `gh` が期限前に鍵を自動で取り替えるので、利用者が再ログインする手間はない。今は希望者だけが使える試験提供で、将来は新規ログインの標準にする予定だという。

### [GitHub Actions Self-hosted runnerをお手軽にスケールさせる ghalet](https://songmu.jp/riji/entry/2026-10-24-scaling-github-actions-runners-with-ghalet.html)
<!-- categories: GitHub Actions, CI, OSS -->

GitHub Actions のジョブを自前のマシンで同時に複数こなすためのツール「ghalet」を、作者がブログで公開した。自前の実行環境（Self-hosted runner）は、標準のままだと1台で1ジョブずつしか動かせない。公式の拡張手段は Kubernetes 前提で大がかりだが、ghalet は Go 製の常駐プログラム1つで済む。自宅の Mac mini でも動くので、小さなチームでCIを手元に置きたいときの選択肢になる。

### [[アップデート] ElastiCache Serverless for Valkey がオンライン移行に対応したので EC2 の Redis OSS から移してみた](https://dev.classmethod.jp/articles/amazon-elasticache-serverless-valkey-online-migration)
<!-- categories: AWS, Redis -->

自前で運用している Redis を、止めずに AWS の管理型キャッシュへ移せるようになった。DevelopersIO が、EC2 上の Redis から ElastiCache Serverless for Valkey へ実際に移して手順を確かめている。Valkey は Redis から分かれたオープンソース版で、移行元は Redis 4.0〜7.2 などのクラスター構成が対象だ。サーバーの面倒を見る手間を減らしたいチームには、移行のハードルが下がる。

### [Node2Shell evolves to HTTP2Shell, blast radius affects many HTTP libs and apps](https://www.aikido.dev/blog/python-packages-vulnerable-node2shell-brotli-cve-2026-111497)
<!-- categories: Security, Node.js, Python -->

Node.js で見つかった圧縮データの展開に潜む欠陥が、ほかの言語やHTTPを扱う多くのソフトにも広がっていると分かった。セキュリティ企業 Aikido によると、原因は Google の圧縮形式 Brotli の展開処理で、細工したデータでメモリを壊しコードを動かせる。根本の修正は2月に入っていたが、脆弱性と認識されず、正式版に載っていなかった。[Node.js のセキュリティ更新](/blog/2026-10-22/#nodejs--wednesday-october-21-2026-security-releases)を当てただけでは足りず、Python のパッケージや Envoy なども個別に更新が要る。

### [Ruby で任意のユーザー入力を渡してはいけないメソッド - @znz blog](https://blog.n-z.jp/blog/2026-10-09-ruby-insecure-methods.html)
<!-- categories: Ruby, Security -->

Ruby で外から来た文字列を渡すと危ないメソッドを、著者がブログで一覧にまとめた。`eval` やコマンド実行だけでなく、`send` や YAML の読み込み、正規表現の組み立ても対象だ。これらは「渡したアプリ側の責任」とされ、Ruby 本体の脆弱性としては扱われない。直前の[Onigmo の不具合修正](/blog/2026-10-24/#ruby-40934123313公開正規表現エンジンの不具合を修正-gitlabの任意コード実行の脆弱性に関連)のように、本体更新だけでは防げない穴を見直す手がかりになる。

### [Twelve years of distributed SQLite](https://philipotoole.com/twelve-years-of-distributed-sqlite)
<!-- categories: SQLite, Distributed Systems, Database -->

SQLite を複数台で複製して動かす「rqlite」の作者が、この分野の12年を振り返った。2014年に合意の仕組み（Raft）と SQLite を組み合わせたのが始まりで、今では十数のプロジェクトが並ぶ分野になったという。著者は、出資や買収を受けたのは複製を「有料のサービス」に仕立てた側だったと指摘する。[Supabase による Turso の買収](/blog/2026-10-04/#supabase-raised-150m-led-by-singapores-gic-and-agrees-to-acquire-turso-which-offers-a-database-optimized-for-ai-agents-for-an-undisclosed-sum)のような動きを、歴史の流れの中で捉え直せる。

### [How close can pure functional programming get to C?](https://rtfeldman.com/fp-vs-c)
<!-- categories: Roc, Performance, C -->

純粋な関数型言語でも、C で書いた最速級の実装にどこまで迫れるかを、Roc 言語の作者が試した。題材はデータ圧縮（DEFLATE）で、徹底的に調整された C のライブラリ libdeflate と比べている。Roc 版の遅れは中央値で数％〜1割弱まで縮まったと著者は報告する。「関数型は遅い」という思い込みを見直す材料になる。

### [SQS のデッドレターキューの中身を、受信の回数を増やさずに確認できるか試してみた](https://dev.classmethod.jp/articles/sqs-dlq-peek-receive-count)
<!-- categories: AWS -->

AWS のメッセージキュー SQS で、失敗したメッセージの置き場（デッドレターキュー）を覗くと何が起きるかを DevelopersIO が検証した。中身を読むだけでも受信回数は増え、標準キューでは増やさずに読む方法はなかった。他の受信者から隠す時間を0にして読むと、1回の呼び出しで同じメッセージが何度も返り、回数が急増した。ただし元のキューへ戻すと回数は1から数え直されるので、再処理への影響はないと分かった。
